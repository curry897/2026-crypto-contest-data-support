# 形式化验证

使用自动化协议验证工具（ProVerif 2.05）在 Dolev–Yao 敌手、**无界会话**的条件下，对方案的关键性质做机械验证。

## 验证场景

敌手完全控制网络，并从一开始就持有一个节点的凭证；用户端对敌手转交的任何审批请求都予以同意；口令与全部长期私钥还在事后被泄露。**在这样最不利的设定下检验下表的性质。**

## 结果

| 查询 | 验证的性质 | 目标 | 结果 |
|---|---|---|---|
| Q1 | 诚实发起方的会话密钥保密，含长期秘密事后泄露（前向安全） | G1 | **成立** |
| Q2 | 运行时接受诚实发起方时，对方确以同一会话运行：不可冒充祖先、兄弟与其他任务 | G3 | **成立** |
| Q3 | 发起方接受运行时时，对方确为其响应：运行时不可冒充 | G3 | **成立** |
| Q4 | 被腐化节点能在其子树内认证并执行（健全性检查：腐化真实生效） | G3 | 与预期一致 |
| Q5 | 任何被执行的操作都在用户批准的范围内——即使敌手为自建节点填写最宽的限制 | G4 | **成立** |
| Q6 | 诚实请求与执行单射对应：每个请求至多执行一次 | G5 | **成立** |
| Q7 | 高风险操作的执行与用户的一次审批单射对应 | G6 | **成立** |
| Q8 | 仅控制网络的敌手无法离线检验口令 | G2 | **成立** |
| Q10 | DiPAKE+：凭证泄露时无法离线猜测口令 | G2 | **成立** |
| Q12 | 撤销记录只能来自用户本人 | G6 | **成立** |

## 要点

- 即便敌手一开始就持有被腐化节点的凭证，会话数不设上限，上述性质依然成立。
- 口令安全被精确地刻画出来：**只有网络敌手时口令不可离线检验；DiPAKE+ 即使凭证被窃，每一次猜测都必须在线查询。**
- 形式化建模在设计阶段直接帮助发现并修补了跨消息、跨会话的细节问题，这些问题单靠功能测试难以发现。
