# 安全性结论

本文列出 DiPAKE 的安全目标、敌手模型与主要定理的**结论**。具体构造、假设细节与证明不在本仓库公开范围内。

## 三重保障

同一套安全目标 G1–G7 由三类相互独立的证据支撑：

1. **可证明安全**：随机预言机模型下的三条主定理，只依赖标准的静态困难假设，并给出敌手优势的具体上界；
2. **形式化验证**：在无界会话、敌手持有被腐化子树凭证的条件下机械验证（见 [`formal-verification.md`](formal-verification.md)）；
3. **系统实测**：36 种攻击全部被拦截，3 项合法操作全部放行；真实大模型提示注入；真实设备部署（见 [`evaluation.md`](evaluation.md)、[`security-tests.md`](security-tests.md)）。

## 敌手模型

敌手是主动敌手，可以：控制整个网络（窃听、篡改、重放、并发会话）；**腐化任意多个智能体**并让它们合谋，获得其完整凭证；泄露运行时的临时秘密或会话密钥；在会话结束后再腐化长期秘密；诱导用户批准请求，或向运行时提交任意请求。

## 安全目标

| 目标 | 含义 |
|---|---|
| G1 | 会话密钥保密，长期秘密事后泄露也不影响已完成的会话（前向安全） |
| G2 | 网络敌手每次交互至多排除一个候选口令；DiPAKE+ 下凭证泄露也不能离线猜测口令 |
| G3 | 认证到的对端只能是诚实持有者或被腐化子树内的路径：不可上溯、横移、跨任务 |
| G4 | 被执行的请求满足全部限制，不超出用户批准的范围 |
| G5 | 每个请求至多执行一次；已撤销的任务被拒绝；累计预算不超限 |
| G6 | 审批绑定具体请求、一次有效；撤销只能由用户本人发起 |
| G7 | 域外观察者无法区分握手成败，也看不到身份与委托结构 |

## 主要定理（结论）

- **定理 1（认证密钥交换安全）**：新鲜会话的密钥与随机值不可区分；对不在腐化范围内的对端，具有双向显式认证；握手对外部观察者保密。敌手没有凭证时，与口令相关的优势只有“每次在线交互排除一个候选口令”。
- **定理 2（子树隔离）**：敌手**不能冒充被腐化节点的祖先或兄弟，不能冒充其他任务中的任何节点**；多个节点合谋时，其能力仅为各自子树的并集。
- **定理 3（授权可靠性）**：诚实的运行时执行的每个请求，都满足路径真实、权限收缩（不超出用户批准的范围）、不可重放与撤销生效、审批与撤销绑定用户本人。

> 定理 3 不依赖智能体是否诚实地收缩权限，也不依赖智能体能否抵御提示注入：即使用户批准的任务根之下的节点全部失陷，被执行的请求也不会超出用户批准的范围。

## 部署建议

1. 推荐部署 DiPAKE+，把每次口令猜测都变为受限速、可审计的在线查询；
2. 按最小权限编写策略，高风险操作设置逐次审批；
3. 多实例部署时保持一致的记账与撤销状态；
4. 审计日志精确到“哪一条委托路径”发起了操作。
