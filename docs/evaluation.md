# 测试与评估

测试数据由原型实现产生，汇总数据在 [`bench/data/`](../bench/data)，图在 [`bench/figures/`](../bench/figures)。

## 1. 威胁模型下的攻击测试

39 个用例：8 类共 36 种攻击全部被拦截，3 项合法操作全部放行。完整清单见 [`security-tests.md`](security-tests.md)。

| 类别 | 用例数 | 示例 |
|---|---:|---|
| 身份冒充 | 6 | 下级冒充祖先；兄弟互相冒充；跨任务冒充；不知口令者自建凭证 |
| 委派滥用 | 3 | 给下级写更宽的策略；没有委托余量仍继续派生；改写自己的策略 |
| 越权调用 | 8 | 受提示注入的节点外传数据；`..` 与编码混淆；前缀混淆；过期后调用 |
| 篡改与重放 | 8 | 篡改参数；转投请求；重放；跨会话冒用会话编号 |
| 撤销 | 4 | 兄弟撤销；撤销后继续调用；伪造撤销令牌 |
| 逐次审批 | 4 | 未审批执行；伪造令牌；令牌挪用到另一请求；令牌重复使用 |
| 累计预算 | 2 | 兄弟分支各自“用满”上级额度；超出调用次数 |
| 协议隐私 | 1 | 旁观者按消息长度判断握手成败 |

**累计预算的并发测试**：5 个兄弟分支并发发起 50 MiB 上传，共享的 20 MiB 预算一字节也没有被突破。

## 2. 真实大模型的提示注入（InjecAgent）

用 InjecAgent 基准（`base` 设置，1054 个用例）和真实的本地大模型生成越权调用，再把保存下来的模型输出回放到完整的 DiPAKE 网关：
回放经过完整的运行时把关，最终落到进程内的模拟后端，没有外部副作用。

| 运行 | 用例 | 无防护时注入成功率（ASR-all） | 正常调用 | 经 DiPAKE 网关的越权调用 |
|---|---:|---:|---|---|
| Mac M3 Pro，Llama 3.1 8B | 1054 | 31.0% | 1054/1054 放行，0 误拒 | 第一阶段 364/364 拦截；第二阶段（窃取外发）115/115 拦截 |
| RTX 5090，Llama 3.1 8B | 1054 | 30.3% | 1054/1054 放行，0 误拒 | 第一阶段 365/365 拦截；第二阶段（窃取外发）105/105 拦截 |
| Mac M3 Pro，Llama 3.2 3B | 1054 | 0.2% | 1054/1054 放行，0 误拒 | 注入几乎不成功，其余经网关逐级裁决 |

- 在无防护时，8B 模型约三成的用例会被注入成功；接入 DiPAKE 后，这些越权调用在到达后端之前被拒绝，**同时 3162 次正常调用没有一次被误拒**。
- 一级策略只允许该用例中**合法的** `User Tool`，不使用攻击标签构造策略。
- **两级委派**：根策略允许用例涉及工具包的全部工具，子凭证只允许 `User Tool`。8B 的 479 / 470 次攻击回放全部在第 2 级被拒绝——根可以做的事，子节点依然做不了。

图：[注入成功率与拦截（PDF）](../paper/figures/ch6_llm_injection.pdf)

方法与回放路径见 [`../results/injecagent/README.md`](../results/injecagent/README.md)。

## 3. 真实设备上的多级委派部署

环境：3 台 Raspberry Pi 5（4 核 Cortex-A76，8 GB，Debian 13）经无线局域网互联（往返时间约 7–20 ms），1 台笔记本作为用户侧设备（可信客户端与审批服务器，口令只在这里输入）。口令域启用 DiPAKE+。

**委派链**：用户批准一项 30 分钟的巡检任务后，委派沿 A→B→U→R→E 逐级进行，深度为 5（用满最大深度），其中两次是**跨设备**的远程委派，两次是本机离线派生；另有一条兄弟分支 A→C。摄像头真实拍照，告警灯真实点亮。

**逐级约束**：叶子 E 发出 13 组探测（共 19 次请求），每组恰好触及某一级引入的限制：

| 限制类型 | 在哪一级被拒绝 |
|---|---|
| 时长、工具种类 | 第 5 级 |
| 调用次数、不能上传 | 第 4 级 |
| 机柜范围、不能拍摄、时长 | 第 3 级 |
| 不含重启 | 第 2 级 |
| 区域范围、任务有效期 | 第 1 级 |
| 路径穿越（明文与编码） | 资源规范化 |
| 继续向下委派 | 派生失败（无委托余量） |

19 次请求的判定全部符合预期；第 1 到第 5 级每一级都至少有一条请求在该级被拒绝。被拒绝的请求在设备日志中没有执行记录。同一组探测在两次独立部署（基础版与 DiPAKE+）中结果一致。

**跨设备安全测试**（真实网络）：

| 测试 | 结果 |
|---|---|
| 被窃凭证调用其他机柜或其他工具 | 拒绝 |
| 被窃凭证继续向下委派 / 用于另一项任务 | 派生失败 / 握手失败 |
| 撤销下级子树、撤销整项任务后再调用 | 分别以“路径已撤销”“任务已撤销”被拒绝，设备未执行 |
| 抓包后原样重放工具调用 | 记录层判定为重放，设备未执行 |
| 绕过网关直接访问设备工具服务 | 被防火墙拒绝 |
| 用错误口令签发任务 | 签发失败，审批服务器留下一条查询记录 |

**撤销是即时的**：撤销状态由网关统一维护，下级设备不需要收到任何通知，不存在撤销消息传播的时间窗口。

**机器狗**：把委派链延伸到一台机器狗（A→B→C→D→M，深度 5），每一级收窄一种物理约束（速度、活动范围、指令条数、转向角度、动作种类），以机器狗是否**实际动作**为最终判据：每条越权指令都在引入该限制的层级被拒绝，机器狗没有做出任何越权动作；用户撤销任务后机器狗不再响应任何新指令。

## 4. 性能

三种环境、每项测量重复 100 次：Intel Xeon 2.1 GHz（4 核）、Apple M3 Pro（12 核）、Raspberry Pi 5。

| 指标 | 结果 |
|---|---|
| 一次完整握手（双方计算） | 数毫秒（Xeon、M3 Pro）至数十毫秒（Raspberry Pi 5），**不随委托深度增长** |
| 离线委派一份子凭证 | 约 1 ms |
| 运行时把关（会话已建立） | 经把关仅比直连后端增加约 1 ms |
| 多子任务并发 | 吞吐与延迟随并发平稳扩展 |
| 一次为 N 个子智能体委派 | 线性扩展 |
